# Telegram 本地批量下载器 v0.1.2

面向 Windows 10/11 x64 与 macOS 的独立本地工具。通过自己的 Telegram API 应用与账号正常登录，扫描频道/群组中当前账号可以访问的图片、视频消息，建立队列并分段写入磁盘。**无需打开 Telegram 网页，也不需要逐个打开视频。** 软件免费，不使用付费下载服务。

这是用户选择的“第二种方案”。原来的 Tampermonkey 下载脚本和单文件下载功能不需要改动；两者独立运行。本程序不负责安装油猴脚本。

## 最快开始：Windows 便携版

1. 将 Windows 便携压缩包完整解压到一个自己可写的目录，例如 `E:\TelegramDownloader`。不要直接在压缩包内运行，也不要只拿走 EXE；保留同级 `_internal` 文件夹。
2. 双击 `TelegramBatchDownloader.exe`。不需要安装 Python、Chrome 扩展或其他服务。
3. 首次打开“连接账号”。在 [Telegram 官方开发者页面](https://my.telegram.org) 按官方流程取得**自己的** API ID 和 API Hash，填入本机窗口。
4. 如果本机访问 Telegram 需要代理，在程序中填入现有代理，例如 `socks5://127.0.0.1:7890` 或 `http://127.0.0.1:7890`。这里只是格式示例，端口必须以自己的代理软件配置为准。“读取系统代理”只读取现有 Windows 手动代理，不修改系统设置；Chrome 扩展代理、PAC 和 TUN 不一定等同于可用的本地 HTTP/SOCKS 代理。留空为直连。此版本不支持带用户名和密码的代理。
5. 点击“连接 / 恢复登录”，上方应立即显示“正在连接”。连接和会话检查合计最多等待约 30 秒，可点击“取消连接 / 登录”。显示“已连接 Telegram，尚未登录”后，发送验证码按钮才启用。在本机输入以 **`+国家区号`** 开头的手机号（大陆号码为 `+86` 后接自己的手机号），点击“发送验证码”。在自己的 Telegram 已登录设备或平台提供的接收方式中查看验证码，填入窗口并点击“验证并登录”。启用两步验证时，再输入本机窗口要求的密码并再次验证。验证码请求和登录验证各有约 45 秒超时，不会自动反复请求验证码。
6. 在“批量下载”输入 `@频道用户名`、频道/消息链接，或点击“读取已加入频道”选择私有频道。不会自动加入频道，也不接受邀请链接自动加入。
7. 选择保存目录、图片/视频类型及日期范围。默认检索最近 **500 条匹配类型的媒体消息**；日期以北京时间计算，结束日期包含当天。上限 `0` 表示尝试遍历当前账号可访问的匹配媒体历史，仍受 Telegram 返回范围和权限限制。首次建议用 10–20 条验证。
8. 点击“扫描并加入队列”，检查发现的数量，然后点击“开始 / 继续”。默认文件并发 2，可设 1–3；视频最多同时下载 1 个，图片可使用剩余文件并发。

**API Hash、验证码、两步验证密码和会话文件都不要发到聊天里。** 只在自己电脑的本机窗口输入。已加密保存的登录会话下次点击“连接 / 恢复登录”即可复用；程序不在启动时自动联网。

### 从 0.1.0 / 0.1.1 升级

先退出旧版，保留原来的 `state`、`downloads` 和自己选择的下载目录。将新版 EXE、完整 `_internal` 文件夹及说明文档更新到原程序目录，可以沿用原记录；也可以解压到新目录重新填写本机配置。不要在旧程序仍运行时覆盖它或同时让两份程序写同一数据目录。0.1.2 没有改变现有任务数据库和 DPAPI 加密格式。

### 连接按钮看似没有反应

0.1.0 只在底部日志输出连接结果，且“网络已连接、尚未登录”没有明确状态。0.1.1 已在窗口上方和账号页显示连接状态、错误及下一步，并固定保留日志区域。API 配置无效会立即提示，连接超时会恢复按钮，发送验证码前检查国家区号。

如果你使用 Clash、v2rayN 或其他代理软件，**代理栏填软件实际监听的本地 HTTP/SOCKS 地址**；留空会直连。浏览器或 Telegram 桌面版能用，不足以证明本程序能直连。“读取系统代理”读不到配置时会明确提示，需要从代理软件查看端口后填写，不会猜测端口。

## 有哪些功能

- 视频和图片分别分类保存，文件名为 `频道_消息ID_北京时间日期.扩展名`，过滤 Windows 非法字符。同名文件保留原文件，使用 `(1)` 等后缀保存新文件。
- 队列状态包括等待、下载、暂停、成功、失败。可暂停、继续、停止、重试失败及导出当前频道的全部任务/错误记录。停止和暂停均保留队列与校验片段，不自动删除文件。
- 0.1.2 优先调度已有检查点的任务，再按已保存比例优先收尾；待续传任务也会排到等待列表前面。暂停、恢复、重启不再把它们放到全新任务后面。网络失败达到每轮 3 次上限后仍需点击“重试失败”；不会无限重试。
- 并发数是同时下载的文件数，不是磁盘上 `.part` 的数量上限。暂停或失败留下的片段会保留，因此 `.part` 可以多于两个；完成后自动改为正式文件。
- SQLite 持久化任务，按本机账号指纹、频道、消息与媒体 ID 去重。重新打开程序、恢复登录后可继续上次频道的记录。
- 按 512 KiB 分段读取并顺序写入 `.part`。较大视频最多预读两个分段，所有文件合计最多两个附件数据请求同时进行；即便响应先后颠倒，也只按正确偏移交给写盘。每块完全写完再处理下一块，缓存保持小规模，不把整个视频放入内存。完成后检查长度、刷新磁盘、关闭文件，并保存 SHA-256，随后才标记成功。
- 速度显示为近期约 15 秒的平均值。0.1.0 超过两秒没有新分段就显示 0，低速网络下会出现“0/100 KiB”反复跳变；新版修正这一显示，并预读少量分段以减少请求往返等待。真实速度仍受代理线路、账号和 Telegram 服务端限制，不保证固定提速倍数。程序启动日志会显示原生加密加速库是否已加载。
- 每约 1 秒在对齐的分片边界保存一次经过 `fsync` 的检查点。恢复时重新取得消息元数据，核对媒体 ID 和大小，再核对本地前缀 SHA-256。未提交尾部会丢弃；损坏前缀会重新下载，不会拼接进成品。暂停/意外退出后可能回退到最近检查点，故进度稍有回退是正常现象。
- 普通临时网络错误每轮最多尝试 3 次，单个媒体失败后其他任务继续。Telegram `FloodWait` 等待时间会保存并在恢复后遵守。明确的访问拒绝不自动或手动反复重试；登录失效和磁盘写入错误会暂停整个队列。
- 重新扫描会检查已完成文件是否存在及大小是否变化；缺失时重新排队。任务记录本身不证明磁盘文件仍然存在。不会每次重扫描都重新计算全部完成文件的 SHA-256。

移动已完成视频后，应先关联新路径，防止旧路径失效造成重下。本地只读校验与备份后关联路径的辅助脚本用法见 [移动文件与下次去重](docs/MOVED-FILES.md)；这些脚本在源码目录中独立运行。

目录示例：

```text
选择的保存目录/
  jiepairewu/
    videos/jiepairewu_123456_20261018.mp4
    photos/jiepairewu_123457_20261018.jpg
```

扫描时改变保存目录，会让本次扫描发现的未完成任务从新目录重新下载；旧目录中的片段保留，不自动删除。已完成且存在的文件继续保持完成状态，不会因更换目录重复下载。

## 保存限制与扫描范围

本方案直接使用 Telegram 的正常登录、历史搜索和附件读取能力，不依赖“先打开播放器才出现的网页地址”。因此，与油猴版本相比，可以直接把 API 返回的媒体加入队列。

网页“禁止转发/保存”的界面标志与服务端是否允许此账号读取附件并非同一层能力。本工具不会仅凭网页按钮是否存在就把所有视频判为不可下载；它也**不能保证任何受限频道都能批量下载**。如果 Telegram API 拒绝访问或下载、消息被删除、账号没有访问权限，任务会停止并记录错误。不会提取浏览器 Cookie、登录凭据、修改账号鉴权、自动加入频道、转发消息或调用付费解锁服务。

扫描数量是**本次 API 返回并检索的媒体消息数量/本地记录数量**，不等于频道全量历史总数。私有频道、隐藏历史、删除媒体、自毁媒体、圆形视频消息及 Telegram 没有返回的内容不保证可发现。本版仅处理普通图片与视频，不下载聊天文本、音频、私聊或秘密聊天。当前列表最多显示 200 项，完整队列和错误记录仍在 SQLite，可导出查看。

## 本机数据与退出

程序目录需要可写。数据保存在 EXE 旁的 `state/`：

- `profile.json`：API ID、保存目录、代理及使用 **Windows 当前用户 DPAPI（Windows）/ 登录钥匙串（macOS）加密**的 API Hash/登录会话。没有明文 `.session` 文件，不保存手机号、验证码或两步验证密码。
- `tasks.sqlite3`：频道、消息 ID、文件名/路径、任务状态、校验值及错误记录。频道与文件名等元数据没有加密。账号只以带随机盐的本机指纹区分。

下载直接发生在本机与 Telegram 之间，没有本工具的第三方转存、上传或遥测服务。DPAPI 保护的是磁盘上的秘密；正在运行的同一 Windows 用户进程仍可使用已解密会话。不要把整个 `state` 文件夹当作公开测试材料。换 Windows 用户或换电脑可能无法解密，届时在新的程序数据目录重新登录。

关闭窗口会暂停并保存片段；可正常退出后备份 `state` 和下载目录。不要同时启动两份程序写入同一数据目录。如需彻底重建配置，可退出后将 `state` 改名为备份，再重新启动。原会话如需失效，请在自己的 Telegram 客户端“设备/活动会话”正常结束它；只删除本地记录不会撤销服务器会话。

## 已知限制与错误处理

- **自动化测试不连接真实账号，也未对 `@jiepairewu` 做完整在线下载验收。** 已提供离线测试与 Windows 程序启动检查，真实文件下载、API 返回范围及频道权限仍以你本机的实际结果为准。
- 下载内容按原附件字节保存，不做转码或修复。大小与本地 SHA-256 校验可发现传输/片段问题，不是 Telegram 提供的整文件来源签名，也不能把源端已经损坏的视频修好。播放器是否支持源编码取决于本机播放器。
- 断点支持以当前消息仍包含同一媒体为前提；消息媒体被替换、删除或访问撤销时，不会把旧片段接到其他文件上。服务器引用过期会重新读取消息后有限重试。
- Windows 文件系统和 SQLite 是两个独立存储介质。在最终文件改名成功、完成记录提交之前发生极端断电时，下次可能重新下载并生成带编号的副本；不会覆盖原文件。正常暂停恢复会使用检查点。
- 长路径、网络盘、杀毒软件占用、磁盘空间不足可能使写盘失败。遇到 `DISK_*` 先检查磁盘后再点重试。过大的异常片段会保留并停止，可选择新目录重新扫描；不要把不明 `.part` 文件手工拼接。
- `ACCESS_DENIED`：服务端拒绝，停止此任务。`AUTH_REQUIRED`：重新连接/登录。`FLOOD_WAIT`：遵守提示等待。`NETWORK`：核对本机网络和代理。`SOURCE_CHANGED`：重新扫描发现新的媒体记录。
- 本工具没有自动更新、自动清理磁盘和多频道同时运行功能。任务数据库保留去重历史；“停止”不删除历史记录。

## 源码运行与测试

便携版用户可以跳过本节。源码版使用 Python 3.12 x64；Tkinter 是官方 Windows Python 的标准组件。依赖版本固定在 `requirements.txt`，无需 Node.js 或复杂构建链。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
.\.venv\Scripts\python.exe scripts\run_tests.py
```

也可以依次双击 `setup-source.cmd`、`launch-source.cmd`；运行测试用 `test.cmd`。依赖首次安装需要联网；程序运行没有付费依赖。

macOS（源码运行）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-runtime.lock.txt
.venv/bin/python app.py
```

- 需要使用 **自带 Tk 的 Python**（python.org 官方安装包或 `brew install python-tk`），否则启动会报 `No module named '_tkinter'`。
- API Hash 与登录会话保存在登录钥匙串（Keychain），`profile.json` 只有随机条目名，不含明文；首次保存由系统弹窗确认。
- “读取系统代理”调用 `scutil --proxy`，只识别手动配置的 HTTP/SOCKS 代理，不识别 PAC 与 TUN。
- 界面字体自动切换为苹方；单实例锁使用 `flock`。

macOS 打包版（双击启动）：

```bash
bash scripts/build-macos.sh
open dist/TelegramBatchDownloader.app
```

- 输出 `dist/TelegramBatchDownloader.app`，显示名“Telegram 批量下载器”，含自绘图标与菜单栏。
- 打包版数据保存在 `~/Library/Application Support/TelegramBatchDownloader`。沿用源码版队列时，先退出程序，再执行：
  `cp -R state "$HOME/Library/Application Support/TelegramBatchDownloader/"`
- 首次打开如被 Gatekeeper 拦截，在 Finder 中右键应用选择“打开”。
- 支持 `Command+Q` 退出、菜单栏复制/粘贴/全选、窗口大小与位置记忆。
- 开始下载前会检查保存目录可用空间；磁盘接近写满时会自动暂停队列，不再等到写盘失败。

离线演示（不需要账号，不连接 Telegram，生成的是模拟字节，不是可播放媒体）：

```powershell
.\.venv\Scripts\python.exe app.py --demo --data-dir .\qa\demo
```

构建 Windows 便携程序：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
powershell -File .\scripts\build.ps1
```

输出 `dist/v0.1.2/TelegramBatchDownloader/` 整个目录。发布包不应包含开发机的 `.venv`、`state`、下载文件或 QA 数据。第三方版权与许可见 `THIRD-PARTY-NOTICES.md` 和 `licenses/`。

源码结构：`transport.py` 只做正常 Telegram API 适配，`engine.py` 管理队列和检查点，`storage.py` 管理 SQLite，`secure.py` 管理 DPAPI，`app.py` 提供 Windows 界面。更改说明见 [CHANGELOG.md](CHANGELOG.md)，测试范围见 [docs/TESTING.md](docs/TESTING.md)。
